## Notes for the reviewer

- B8 was "plausible". Proven at the function level: the nudge date is the last estimate's timestamp plus the stale gap, or the moment of the sync when already stale, and every HealthKit refresh (including background wakes) calls `syncFreshnessNudge`. Whether Apple stamps VO2 max at workout time does not matter for the night-wake path.
- B9 was "plausible". The range side is proven by `b9_sameDayPickCoversTheWholeDay`. That a date-only `DatePicker` keeps its bound value's clock time was not run on a device; the fix no longer depends on it, because both the store and the sheet now work in whole days.
- B8 changed two existing test fixtures, not assertions: `OvernightP1Tests.now` was 08:53 UTC and the SM-1 tests in `StateMachineFixTests` used `Date.now`. Both checked exact nudge dates, which now depend on the hour, so they run at noon. Every assertion is unchanged.
- B4 has no pre-fix failing test: the outcome classifier it tests was introduced by the fix. The raw RevenueCat codes in the test (20 pending, 1 cancelled, 10 network) were checked against RevenueCat's generated `ErrorCode.swift`. On the paywall the waiting line uses the existing attempt-message line, which is red; colour was left alone to keep the frozen purchase surface unchanged.
- B7's proof is a source guard (the repository's existing pattern for view wiring), not a behavioural test: the simulator cannot change notification permission from a test.
- B2 shows the permission sentence only when a whole series (two years) is empty after a load, which is also what a customer with no Apple Watch sees. Both cases now get a sentence that is true for them.
- Custom ranges ending today now end at the end of today rather than at the moment of Apply; future readings do not exist, so nothing else reads differently. The two-year cap is now 730 calendar days including both ends.
- The UI test index line is in `project-docs/README.md`, which is this repository's existing docs index (`project-docs/audits/` has no README of its own).
