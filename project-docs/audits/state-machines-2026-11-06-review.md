## What survived, ranked

1. **SM-1**: freshness nudge spacing collapses; a stale Pro user who keeps opening the app gets a nudge about every cold launch, while looking at the app. Certain and repeated, small population.
2. **SM-5**: stale purchase error replaces the paywall's renewal disclosure. Common route (cancel in onboarding, then VO2+ tab), App Review exposure. The audit ranked it 5th.
3. **SM-3**: the once-ever return review moment can be spent by a background relaunch. One lost ask for a minority of new Watch users. The audit called it the common case.
4. **SM-2**: notification toggles and the freshness card ignore a denied permission. The audit ranked it 2nd on an "out of context prompt" premise the default-off toggles contradict.
5. **SM-6**: one free recap after a lapse; reading alerts and nudges continue until the next open. Partly a product call.

Not ranked: SM-4 (UNVERIFIED), SM-7 (NOT A BUG; footer copy fix).

## Product calls

Agree with 1 to 7 and 9 as product calls. Number 3 deserves a look: a returning subscriber whose entitlement resolves during the welcome step finishes onboarding before the Health prompt (`OnboardingView.swift:103-105,121-123`), though the dashboard's Connect button recovers it (`DashboardView.swift:372-378`).

Number 8 is a bug, not a product call: `restoreResultMessage` returns bare English literals (`VO2ConversionCopy.swift:87-89`), against the rule that copy returned from a model or service uses `String(localized:)` (`.claude/rules/localization.md`). A successful restore in Settings shows "VO2+ restored." in English in all 18 other locales (`SettingsView.swift:482`). CONFIRMED-MINOR, outside the state machine scope.

## Missed by the audit

- SM-1 also fires on a cold launch, from the two syncs within seconds noted above. The audit's model ran one sync per open, so it understated the rate. Not a separate bug.
- No other serious state bug found inside the audit's scope.

## Method changes

1. Model every caller of a transition, including the ones that run together on a cold launch. Listing the three `syncFreshnessNudge` callers but replaying only one per open hid the worst case of SM-1.
2. Read defaults and the trigger point before guessing user behaviour. "Out of context prompt" (SM-2) is contradicted by default-off toggles that ask right after the user opts in.
3. Find every writer of shared state before sizing the population. SM-5's commonest writer (onboarding cancel) was missing, so it was ranked too low.
4. When a doc comment states the behaviour, a contradicting user-facing sentence is a copy bug, not a state bug (SM-7).
5. Check that each citation belongs to the function in question (SM-6 cited the reading-alert comment for the recap).
6. Put the mitigations of the same state in the claim: SM-3's moment stays pending, SM-5's `restoreMessage` resets on each tab entry.
7. Do not count a timing-dependent claim whose ordering was never observed; list it separately as UNVERIFIED (SM-4).
8. Prefer a model-free assertion on the real function where one exists. Feeding `nextNudgeDate` its own output proves SM-1's core in two calls, without a replay model whose fidelity a reviewer has to trust.
